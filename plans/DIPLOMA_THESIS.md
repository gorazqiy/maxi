### Глава 1. Теоретические основы разработки интернет-магазинов

#### 1.1. Понятие и классификация интернет-магазинов

Интернет-магазин - это веб-приложение, предназначенное для продажи товаров или услуг через сеть Интернет. Основными функциями интернет-магазина являются:

- Каталогизация товаров (отображение товаров по категориям, с возможностью поиска и фильтрации);
- Управление корзиной покупателя;
- Оформление заказов;
- Приём онлайн-платежей;
- Управление учётными записями пользователей;
- Администрирование (управление товарами, категориями, заказами).

Классификация интернет-магазинов может проводиться по различным признакам:

1. **По модели продаж:** B2C (Business-to-Consumer), B2B (Business-to-Business), C2C (Consumer-to-Consumer).
2. **По типу товаров:** товарные (физические товары), цифровые (электронные товары), смешанные.
3. **По способу реализации:** коробочные решения (готовые CMS), SaaS-платформы, индивидуальная разработка.
4. **По масштабу:** малые, средние, крупные (маркетплейсы).

#### 1.2. Обзор современных технологий веб-разработки

Современная веб-разработка предлагает широкий спектр технологий. Основные подходы к созданию веб-приложений включают:

**Монолитная архитектура** - все компоненты приложения (клиентская часть, серверная часть, бизнес-логика) реализованы в рамках одного проекта. Простота разработки и развёртывания, но ограниченная масштабируемость.

**Микросервисная архитектура** - приложение разбивается на независимые сервисы, каждый из которых отвечает за свою функциональность. Сложнее в разработке, но лучше масштабируется.

**SPA (Single Page Application)** - клиентская часть загружается один раз, дальнейшая работа происходит без перезагрузки страницы. Обеспечивает быстрый отклик и плавную навигацию.

**SSR (Server-Side Rendering)** - страницы генерируются на сервере и отправляются клиенту. Лучше для SEO, но требует больше ресурсов сервера.

#### 1.3. Архитектура современных веб-приложений

Современное веб-приложение электронной коммерции обычно строится по клиент-серверной архитектуре и включает следующие компоненты:

1. **Клиентская часть (Frontend)** - отвечает за отображение данных и взаимодействие с пользователем. Реализуется с использованием JavaScript-фреймворков (React, Vue.js, Angular).

2. **Серверная часть (Backend)** - реализует бизнес-логику, обрабатывает запросы клиента, взаимодействует с базой данных. Реализуется на Node.js (Express), Python (Django), Java (Spring), C# (ASP.NET).

3. **База данных** - хранит информацию о товарах, пользователях, заказах. Используются реляционные БД (PostgreSQL, MySQL) или NoSQL-решения (MongoDB).

4. **Платёжный шлюз** - сервис для обработки онлайн-платежей (ЮKassa, Stripe, PayPal).

Взаимодействие компонентов в разрабатываемой системе:

```
Клиент (React SPA)
    |
    | HTTP/HTTPS (REST API)
    |
Express Сервер
    |
    | Sequelize ORM
    |
PostgreSQL База данных

Express Сервер -> ЮKassa (создание платежей)
Клиент -> ЮKassa (перенаправление на оплату)
ЮKassa -> Express Сервер (webhook-уведомления)
```

#### 1.4. Анализ требований к интернет-магазину товаров собственного производства

На основе анализа бизнес-процессов компании «Макси» были выявлены следующие функциональные требования к интернет-магазину:

**Пользовательские функции:**

- Просмотр каталога товаров с разбивкой по категориям.
- Поиск товаров по названию.
- Фильтрация товаров по цене и категории.
- Сортировка товаров (по цене, по названию).
- Просмотр детальной информации о товаре (описание, состав, изображения).
- Регистрация и авторизация.
- Управление корзиной (добавление, удаление, изменение количества).
- Оформление заказа с оплатой через платёжную систему.
- Просмотр истории заказов.
- Редактирование профиля (имя, телефон, адрес доставки).

**Административные функции (реализованы на уровне API, интерфейс — в перспективе):**

- Управление товарами (создание, редактирование, удаление) — API с защитой adminOnly.
- Управление категориями товаров (создание, редактирование, удаление) — API с защитой adminOnly.
- Загрузка и удаление изображений товаров — API с защитой adminOnly.
- Просмотр и управление заказами — функционал на стадии планирования.

**Нефункциональные требования:**

- Кроссплатформенность (работа на всех современных браузерах).
- Адаптивный дизайн (корректное отображение на мобильных устройствах).
- Безопасность (защита данных пользователей, безопасная передача данных).
- Производительность (быстрая загрузка страниц, оптимизация запросов).
- Масштабируемость (возможность расширения функционала).

#### 1.5. Обзор существующих решений и обоснование выбора технологий

На рынке представлены как готовые платформы для создания интернет-магазинов, так и инструменты для индивидуальной разработки.

**Готовые платформы и CMS:**

- _Shopify_ - популярная SaaS-платформа, но требует ежемесячной оплаты и ограничивает кастомизацию.
- _OpenCart / WooCommerce_ - бесплатные CMS, но имеют ограниченную производительность и сложности с кастомизацией.
- _Magento_ - мощная, но сложная в освоении и требовательная к ресурсам система.

**Индивидуальная разработка** позволяет получить полностью контролируемое решение, оптимизированное под конкретные потребности бизнеса.

**Обоснование выбора технологий:**

#### 2.2. Проектирование архитектуры приложения

Приложение построено по клиент-серверной архитектуре и разделено на два основных модуля: клиентский (frontend) и серверный (backend). Проект организован как монорепозиторий:

#### 2.3. Проектирование базы данных

База данных интернет-магазина включает 7 взаимосвязанных таблиц, образующих реляционную структуру:

**Таблицы и их связи:**

1. **users** - пользователи системы
   - `id` (INT, PK, автоинкремент)
   - `name` (VARCHAR) - имя пользователя
   - `email` (VARCHAR, UNIQUE) - email
   - `password_hash` (VARCHAR) - хеш пароля
   - `phone` (VARCHAR) - телефон
   - `address` (TEXT) - адрес доставки
   - `role` (ENUM: user, admin) - роль
   - `created_at`, `updated_at` (DATETIME)

2. **categories** - категории товаров
   - `id` (INT, PK)
   - `name` (VARCHAR) - название
   - `description` (TEXT) - описание
   - `image` (VARCHAR) - изображение
   - `created_at` (DATETIME)

3. **products** - товары
   - `id` (INT, PK)
   - `name` (VARCHAR) - название
   - `description` (TEXT) - описание
   - `composition` (TEXT) - состав
   - `price` (DECIMAL) - цена
   - `category_id` (INT, FK -> categories.id)
   - `created_at`, `updated_at` (DATETIME)

4. **product_images** - изображения товаров
   - `id` (INT, PK)
   - `product_id` (INT, FK -> products.id, CASCADE)
   - `image_url` (VARCHAR) - URL изображения
   - `sort_order` (INT) - порядок сортировки

5. **cart_items** - элементы корзины
   - `id` (INT, PK)
   - `user_id` (INT, FK -> users.id)
   - `product_id` (INT, FK -> products.id)
   - `quantity` (INT) - количество
   - `created_at`, `updated_at` (DATETIME)

6. **orders** - заказы
   - `id` (INT, PK)
   - `user_id` (INT, FK -> users.id)
   - `total` (DECIMAL) - общая сумма
   - `status` (ENUM: pending, paid, shipped, delivered, cancelled)
   - `payment_url` (VARCHAR) - ссылка на оплату
   - `yookassa_payment_id` (VARCHAR) - ID платежа в ЮKassa
   - `created_at`, `updated_at` (DATETIME)

7. **order_items** - позиции заказа
   - `id` (INT, PK)
   - `order_id` (INT, FK -> orders.id, CASCADE)
   - `product_id` (INT, FK -> products.id)
   - `quantity` (INT)
   - `price` (DECIMAL) - цена на момент заказа

**Связи между таблицами:**

- `categories` 1---\* `products` (категория содержит много товаров)
- `products` 1---\* `product_images` (товар имеет много изображений)
- `users` 1---\* `cart_items` (пользователь имеет много элементов в корзине)
- `products` 1---\* `cart_items` (товар может быть добавлен в корзину много раз)
- `users` 1---\* `orders` (пользователь создаёт много заказов)
- `orders` 1---\* `order_items` (заказ включает много позиций)
- `products` 1---\* `order_items` (товар может присутствовать в многих заказах)

Спроектированная схема базы данных удовлетворяет следующим принципам:

1. **Нормализация** - данные организованы в отдельные таблицы, что исключает избыточность.
2. **Целостность ссылок** - внешние ключи обеспечивают согласованность данных.
3. **Транзакционность** - операции оформления заказа выполняются в рамках транзакции.
4. **Индексация** - поля, участвующие в поиске (email, name, category_id), проиндексированы.

#### 2.4. Проектирование пользовательского интерфейса

Пользовательский интерфейс спроектирован с учётом принципов UX-дизайна и включает следующие страницы:

1. **Главная страница (`/`)** - отображает каталог товаров с боковой панелью фильтров (категории, цена, сортировка, поиск). Реализована пагинация для удобной навигации по каталогу.

2. **Страница товара (`/product/:id`)** - детальная информация о товаре: название, цена, описание, состав, изображения (слайдер с миниатюрами), кнопка добавления в корзину.

3. **Корзина (`/cart`)** - список добавленных товаров с возможностью изменения количества, удаления и очистки корзины. Отображается итоговая сумма и кнопка перехода к оплате.

4. **Авторизация (`/login`) и регистрация (`/register`)** - формы для входа и создания учётной записи.

5. **Профиль (`/profile`)** - информация о пользователе, форма редактирования профиля, история заказов с отображением статуса каждого заказа.

```typescript
export const getAll = async (req: Request, res: Response) => {
   const {
      categoryId,
      minPrice,
      maxPrice,
      sort,
      search,
      page = "1",
      limit = "12",
   } = req.query;
   const where: any = {};

   if (categoryId) where.category_id = Number(categoryId);
   if (minPrice || maxPrice) {
      where.price = {};
      if (minPrice) where.price[Op.gte] = Number(minPrice);
      if (maxPrice) where.price[Op.lte] = Number(maxPrice);
   }
   if (search) where.name = { [Op.iLike]: `%${search}%` };

   // Сортировка
   let order: any = [["created_at", "DESC"]];
   if (sort === "price_asc") order = [["price", "ASC"]];
   if (sort === "price_desc") order = [["price", "DESC"]];
   if (sort === "name") order = [["name", "ASC"]];

   // Пагинация с findAndCountAll
   const { rows: products, count: total } = await Product.findAndCountAll({
      where,
      order,
      limit: Number(limit),
      offset: (Number(page) - 1) * Number(limit),
      include: [
         { model: Category, as: "category", attributes: ["id", "name"] },
         {
            model: ProductImage,
            as: "images",
            attributes: ["id", "image_url", "sort_order"],
         },
      ],
   });

   res.json({
      products,
      total,
      page: Number(page),
      totalPages: Math.ceil(total / Number(limit)),
   });
};
```

##### 3.2.3. Аутентификация и авторизация

Аутентификация реализована на основе JWT (JSON Web Token) в middleware [`server/src/middleware/authMiddleware.ts`](server/src/middleware/authMiddleware.ts):

1. Пользователь отправляет email и пароль на `/api/auth/login`.
2. Сервер проверяет учётные данные и возвращает JWT-токен.
3. Токен сохраняется в `localStorage` на клиенте.
4. При каждом запросе к защищённым маршрутам токен передаётся в заголовке `Authorization: Bearer <token>`.
5. Middleware `protect` проверяет токен и загружает данные пользователя.
6. Middleware `adminOnly` проверяет роль пользователя.

```typescript
export const protect = async (
   req: AuthRequest,
   res: Response,
   next: NextFunction,
) => {
   let token;
   if (
      req.headers.authorization &&
      req.headers.authorization.startsWith("Bearer")
   ) {
      token = req.headers.authorization.split(" ")[1];
   }
   if (!token) return res.status(401).json({ message: "Не авторизован" });

   try {
      const decoded = jwt.verify(token, jwtConfig.secret) as { id: number };
      const user = await User.findByPk(decoded.id, {
         attributes: { exclude: ["password_hash"] },
      });
      if (!user)
         return res.status(401).json({ message: "Пользователь не найден" });
      req.user = user;
      next();
   } catch (error) {
      return res.status(401).json({ message: "Невалидный токен" });
   }
};
```

```typescript
export const useMediaQuery = (query: string): boolean => {
   const [matches, setMatches] = useState(
      () => window.matchMedia(query).matches,
   );

   useEffect(() => {
      const media = window.matchMedia(query);
      const listener = (e: MediaQueryListEvent) => setMatches(e.matches);
      media.addEventListener("change", listener);
      return () => media.removeEventListener("change", listener);
   }, [query]);

   return matches;
};
```

```typescript
export const adminOnly = (
```

#### 4.1. Методы тестирования

В процессе разработки использовались следующие методы тестирования:

2. **Интеграционное тестирование** - проверка взаимодействия между компонентами системы (клиент-сервер, сервер-БД).
3. **Ручное тестирование** - проверка пользовательского интерфейса в различных браузерах и на различных устройствах.
4. **Тестирование API** - проверка всех эндпоинтов REST API.

#### 4.2. Тестирование API

Тестирование API выполнялось с помощью инструментов Postman и curl. Проверялись следующие сценарии:

- **Аутентификация:** регистрация нового пользователя, вход с корректными и некорректными данными, доступ к защищённым маршрутам без токена.
- **Товары:** получение списка с фильтрацией, получение конкретного товара, создание/обновление/удаление (администратором и обычным пользователем).
- **Корзина:** добавление товара, изменение количества, удаление, очистка.
- **Заказы:** создание заказа на основе корзины, получение истории заказов.
- **Платежи:** создание платежа, обработка уведомления.

#### 4.3. Тестирование пользовательского интерфейса

Тестирование пользовательского интерфейса включало:

- Проверку корректности отображения всех страниц в браузерах Chrome, Firefox, Safari, Edge.
- Проверку адаптивной вёрстки на различных разрешениях экрана (1920x1080, 768x1024, 375x667).
- Проверку всех пользовательских сценариев (навигация, поиск, фильтрация, добавление в корзину, оформление заказа).
- Проверку обработки ошибочных ситуаций (пустая корзина, отсутствие товаров по фильтру, неверные учётные данные).

#### 4.4. Развёртывание приложения

Развёртывание приложения может выполняться на любой платформе, поддерживающей Node.js и PostgreSQL. Рекомендуемая конфигурация:

### Приложение А. Исходный код основных модулей

**А.1. Конфигурация Express-сервера** ([`server/src/index.ts`](server/src/index.ts))

Точка входа серверного приложения: настройка middleware (CORS, JSON, статические файлы), подключение маршрутов, синхронизация моделей с БД и запуск сервера.

**А.2. Модель пользователя** ([`server/src/models/User.ts`](server/src/models/User.ts))

Реализация модели User с методами для хеширования пароля (bcrypt) и сравнения паролей. Включает hook `beforeCreate` для автоматического хеширования.

**А.3. Middleware аутентификации** ([`server/src/middleware/authMiddleware.ts`](server/src/middleware/authMiddleware.ts))

Проверка JWT-токена, загрузка пользователя из базы данных, проверка роли администратора.

**А.4. Конфигурация ЮKassa** ([`server/src/config/yookassa.ts`](server/src/config/yookassa.ts))

Функции для создания платежа и получения статуса платежа через API ЮKassa с использованием HTTP Basic Auth и ключа идемпотентности.

**А.5. Redux Store** ([`client/src/store/index.ts`](client/src/store/index.ts))

Настройка Redux store с четырьмя slices: auth, cart, products, categories. Типизированные хуки `useAppDispatch` и `useAppSelector`.

**А.6. Axios Instance** ([`client/src/api/axiosInstance.ts`](client/src/api/axiosInstance.ts))

Настройка Axios с интерцепторами для автоматического добавления JWT-токена в заголовки запросов и обработки ошибки 401 (редирект на страницу входа).

**А.7. Главная страница** ([`client/src/pages/HomePage.tsx`](client/src/pages/HomePage.tsx))

Компонент главной страницы с отображением каталога, панели фильтров, сетки товаров и пагинации. Использует `fetchProducts` и `setFilters` из Redux.

**А.8. Страница товара** ([`client/src/pages/ProductPage.tsx`](client/src/pages/ProductPage.tsx))

Компонент детального просмотра товара с ImageSlider, отображением цены, описания, состава и кнопкой добавления в корзину.

**А.9. Корзина** ([`client/src/pages/CartPage.tsx`](client/src/pages/CartPage.tsx))

Компонент корзины с управлением количеством, удалением товаров, отображением итоговой суммы и интеграцией с ЮKassa для оплаты.

**А.10. Профиль пользователя** ([`client/src/pages/ProfilePage.tsx`](client/src/pages/ProfilePage.tsx))

Компонент профиля с формой редактирования данных и отображением истории заказов со статусами на русском языке.

### Приложение Б. Руководство пользователя

**Б.1. Регистрация и вход**

1. Для использования функционала корзины и заказов необходимо зарегистрироваться.
2. Перейдите на страницу «Регистрация», введите имя, email и пароль.
3. После регистрации или входа вы будете автоматически авторизованы в системе (токен сохраняется в localStorage).
4. Имя пользователя и возможность выйти из системы отображаются в правой части навигационной панели.

**Б.2. Просмотр каталога**

1. На главной странице отображается каталог товаров с пагинацией (12 товаров на страницу).
2. Используйте боковую панель для фильтрации по категориям и цене.
3. Используйте выпадающий список для сортировки (по цене возрастание/убывание, по названию).
4. Поиск товаров осуществляется по названию в строке поиска.
5. Для сброса всех фильтров нажмите «Сбросить фильтры».

**Б.3. Детальная страница товара**

1. Нажмите на карточку товара для просмотра подробной информации.
2. Используйте слайдер для просмотра всех изображений товара (стрелки или миниатюры снизу).
3. Отображается название, цена, категория, описание и состав товара.
4. Нажмите «Добавить в корзину» для добавления товара (требуется авторизация).

**Б.4. Управление корзиной**

1. Перейдите в корзину через ссылку в навигации (отображается количество товаров).
2. Изменяйте количество товаров кнопками "+" и "-".
3. Удаляйте отдельные товары кнопкой "✕" или очистите всю корзину.
4. Отображается итоговая сумма заказа.
5. Нажмите «Оплатить через ЮKassa» для оформления заказа (произойдёт перенаправление на платёжную страницу).

**Б.5. Профиль и заказы**

1. В профиле можно изменить имя, телефон и адрес доставки (email не редактируется).
2. Нажмите «Сохранить изменения» для обновления данных.
3. Раздел «Мои заказы» отображает историю всех заказов со статусами:
   - «В обработке» (ожидает оплаты)
   - «Оплачен» (оплачен через ЮKassa)
   - «Отправлен» (передан в доставку)
   - «Доставлен» (получен покупателем)
   - «Отменён» (заказ отменён)
4. Для каждого заказа отображается номер, дата, сумма и состав заказа.
